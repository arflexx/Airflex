# Deployment

This page covers deploying all three parts of AirFlex: the API server, the
escrow contract, and this documentation site.

## API server

### Required environment variables

The server **will not start** if any of these are missing:

| Variable | Description |
|----------|-------------|
| `JWT_SECRET` | Signs and verifies JWTs. Random string, at least 32 characters. |
| `DATABASE_URL` | PostgreSQL connection string. |
| `ESCROW_CONTRACT_ADDRESS` | Deployed Soroban escrow contract ID (starts with `C`). |

  `stellar_secret_key` values stored in the `wallets` table should be

</Callout>

## Escrow contract

```bash
# Add the required WASM target
rustup target add wasm32v1-none

# Build from the contracts workspace root
cd contracts
stellar contract build
```

Output: `contracts/target/wasm32v1-none/release/airflex_escrow.wasm`.

The currently deployed testnet contract:

|---|---|
| **Network** | Stellar Testnet |

Full deploy walkthrough: [`SOROBAN_DEPLOY_GUIDE.md`](https://github.com/arflexx/Airflex/blob/main/SOROBAN_DEPLOY_GUIDE.md).
Contract CI (`cargo fmt`, `clippy`, tests, WASM build) runs automatically on
every PR via [`.github/workflows/ci.yml`](https://github.com/arflexx/Airflex/blob/main/.github/workflows/ci.yml),
and tagged releases (`v*.*.*`) are packaged via
[`.github/workflows/release.yml`](https://github.com/arflexx/Airflex/blob/main/.github/workflows/release.yml).

## This documentation site

`apps/docs-site` deploys to Vercel at **docs.airflex.io** via
[`.github/workflows/docs-ci.yml`](https://github.com/arflexx/Airflex/blob/main/.github/workflows/docs-ci.yml),
which builds and deploys on every push to `main` that touches
`apps/docs-site/**` (and posts a preview deployment on pull requests).

### One-time setup

1. Create a new Vercel project pointed at this repo with **Root Directory**
   set to `apps/docs-site`.
2. Add `docs.airflex.io` as a domain on that Vercel project (Vercel →
   Project → Settings → Domains) and point its DNS at Vercel per their
   instructions.
3. Add these repository secrets under **Settings → Secrets and variables →
   Actions**:

   | Secret | Where to get it |
   |--------|------------------|
   | `VERCEL_TOKEN` | Vercel → Account Settings → Tokens |
   | `VERCEL_ORG_ID` | `.vercel/project.json` after running `vercel link` locally, or Vercel → Team Settings |
   | `VERCEL_PROJECT_ID_DOCS_SITE` | Same `.vercel/project.json`, or the project's Settings page |

Once those secrets exist, the workflow handles builds and deploys — no
manual `vercel deploy` needed after the first setup.

### Building locally

```bash
cd apps/docs-site
npm install
npm run build   # runs the API/Contract reference generators first, then next build
npm run start   # serve the production build on :3002
```
